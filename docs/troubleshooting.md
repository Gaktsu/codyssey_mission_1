## 트러블슈팅 사례 1

#### 문제 상황

- Dockerfile을 작성하고 이미지가 정상 빌드된 후, 해당 이미지를 기반으로 컨테이너를 만들었으나 바로 종료되는 문제가 발생함

#### 원인 가설

- 원인을 찾기 위해 로그를 확인하였음

#### 원인 확인

```markdown
오류 메시지 : `nginx: invalid option: "-"`
로그 확인 명령어 : `sudo docker logs my-ubuntu`
```

#### 해결 과정

##### 시도 1

- Dockerfile에는 `nginx --version` 을 실행하도록 작성하였다
- nginx의 버전을 확인하는 명령어는 `nginx --version` 이 아닌 `nginx -v` 임을 확인하고 변경한 뒤 재시도 하였지만 다시 종료되는 문제가 발생함

##### 시도 2

- DockerFile에서 CMD 항목을 ["/bin/bash"] 로 변경하여 재빌드하고 컨테이너 생성하여 다시 시도하였다
- 컨테이너가 바로 종료되지 않고, 계속 돌아가는것을 확인하였다

#### 결과 검증

- DockerFile에서 CMD는 첫번째 프로세스를 어떤것으로 실행하는 것임을 확인하였다
- `nginx -v`는 단순히 nginx의 버전만 확인하는 것이므로 실행 후 바로 종료되는것이 원인이었다.

## 트러블슈팅 사례 2

#### 문제 상황

- **index.html**을 포함하여 재빌드 한뒤 컨테이너를 생성해 실행하였다
- 그 후 지정한 포트로 접근을 시도하였지만 **index.html**이 아닌 다른 화면이 나타났다

![Nginx 기본 화면](../images/trouble_shooting/Nginx%20기본%20화면.png)

#### 원인 가설

- 예상되는 원인이 떠오르지 않았다

#### 원인 확인

- Dockerfile 변경하고 이미지 빌드를 안해서 발생하였다.

#### 해결 과정

##### 첫번째 시도

- 포트 충돌을 고려하여 `9876:98`으로 포트를 매핑한 새로운 컨테이너를 생성하였다
- `http://localhost:9876`으로 접속하였지만 빈 페이지를 주었다는 오류가 발생하였다
    - 반대로 `9876`이 아닌 다른 포트로 접속하면 연결할 수 없다는 오류가 발생하였다

![빈 페이지 응답 오류](../images/trouble_shooting/빈%20페이지%20응답%20화면.png)
![연결 안됨 응답 오류](../images/trouble_shooting/연결%20안됨%20응답%20화면.png)

##### 두번째 시도

- 호스트에 설치된 nginx의 기본 설정 파일에 접근하여 확인한 결과 `80`포트를 받는다는 것을 확인하였다
```bash
root@9f8de0b11add:/etc/nginx/sites-available# cat default
server {
        listen 80 default_server;
        listen [::]:80 default_server;
```

- 호스트의 nginx가 영향을 주는것이 아닌가 추측하였
- 호스트의 nginx를 종료한 뒤 다시 `8080:80`로 매핑된 컨테이너를 실행하여 접속한 결과 nginx 기본 화면이 나타났다.

##### 세번째 시도

- Dockerfile 을 통해 빌드를 다시한 뒤 컨테이너를 생성하고 실행한 결과 의도한 화면이 뜨는것을 확인하였다
